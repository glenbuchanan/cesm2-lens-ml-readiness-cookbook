CESM2 LENS ML Readiness Cookbook

This Project Pythia Cookbook covers supervised machine learning readiness on a climate-model large ensemble: one classification question — does the autumn ENSO state predict a wet Front Range winter? — answered on NSF NCAR’s own CESM2 Large Ensemble (the AWS Open Data copy; no account, free egress), walked along the analysis spine of NSF Unidata’s Supervised Machine Learning Readiness, in seven short chapters.

This cookbook is for Earth system scientists, engineers and software staff who are new to machine learning, or who use it without training. It assumes Python at the level of the Xarray tutorial and no ML. The seven chapters take about 2 hours 35 minutes, and each runs on its own in under a minute from a committed table.

Motivation¶

The closest neighbour, in the ProjectPythia organisation though not yet listed in the gallery, is the Precipitation Machine Learning Cookbook, a short scikit-learn introduction (regression on surface observations) that accompanies Unidata’s CyberTraining. The CESM LENS on AWS Cookbook covers reading the CESM1 Large Ensemble, and the scikit-learn Argo (also not yet listed), Landsat ML, xbatcher ML and EO Data Science cookbooks apply machine learning to other data. None yet walks a newcomer through a supervised classifier on a large ensemble, where the members themselves are the unit the split has to respect.

So this cookbook changes exactly one of Unidata’s steps on purpose: the split is by ensemble member, and the forced response and the wet threshold are fit on training members only. Chapter 3 measures what a member-blind split or a transform fitted before the split would do to the score, rather than assuming it. Refinements are promoted on a paired test with a corrected standard error, and the result is always read against the base rate of the same winters.

By the end you will be able to:

  • explain the steps of a supervised analysis (framing → data → split → train → validate → refine → test → justify) and name the failure each step guards against;

  • build and validate a classification model on a climate-model ensemble, reporting precision, recall and a confusion matrix;

  • compare refinement trials as a paired test across runs, so a gap inside the run-to-run spread is not read as a difference;

  • justify the chosen model honestly on measured performance and cost, including when nothing beats the base rate.

Structure¶

Seven chapters, each a notebook that runs on its own in a fresh kernel. Shared code lives in one file, notebooks/lensml.py, which prints a function’s source where a chapter introduces it.

ChapterWhat it does
01 Finding the datathe question as a decision; the intake-esm catalogue on AWS; the committed table
02 The target and the forced responsethe forced response removed on training members only; one pooled “wet” threshold
03 Splitting by ensemble membermember-grouped folds; one model scored three ways to measure two leaks
04 Baselines and the ladderthree rules that fit nothing, then logistic, tree and boosting against the base rate
05 Refinement trialsthe register, the corrected paired t-test, the Bonferroni line, a trial of your own
06 The held-out test, and the justificationthe test, read against no skill and the cost of a false alarm; the limits
07 An out-of-period testthe same members’ SSP3-7.0 winters, scored once under a protocol fixed before the run

Chapters 1–6 carry short Try it prompts; none needs anything outside this repository. The terms are defined in the glossary. Two support files sit beside the chapters: cookbook-render.mjs, a MyST plugin that copies each figure cell’s metadata.alt into the rendered image’s alt text and fails the build if one is missing, and thumbnails/make_thumbnail.py, which redraws the gallery thumbnail from the committed table.

What it finds¶

The signal is weak. The straight-line relation between autumn Niño 3.4 and a wet winter is indistinguishable from zero. The final model, gradient boosting at the base-rate threshold, shows a small precision edge on the held-out members, but that test is not blind: the same 20 members were scored during development. Chapter 7 tests the edge on those members’ untouched SSP3-7.0 winters (2016–2100), under a protocol written before that data was read (self-attested; it ships as notebooks/data/ssp370-test-protocol.md). The edge is not confirmed: it does not replicate under the rule fixed before the run, but the test was small. A true edge of chapter 6’s size would have cleared it only about 42% of the time (chapter 7 prints this), so the result gives no support for a briefing calling the winter statistically wetter, and does not rule such an edge out. Chapter 6 states the limits: a model-world study, on a ~1° grid, of total precipitation, in DJF, for a box that crosses the Divide.

As optional further material, ncar-ml-readiness-course keeps the same data and split and goes on to a small neural network; nothing in it is needed here.

Data¶

notebooks/data/member_winters.csv is the full member-winter table (every member of the ensemble, historical experiment), derived by the cookbook’s own code and committed, so the book builds without touching S3. Every chapter checks its header against the parameters in notebooks/lensml.py, and chapter 1 can re-derive it from S3 (REBUILD = True; about half an hour on a fast link). Chapter 7 alone reads member_winters_ssp370.csv, the same members’ SSP3-7.0 winters. See notebooks/data/README.md.

Running the Notebooks¶

You can either run the notebooks in the Cookbook using Binder or on your local machine.

Running on Binder¶

Until this cookbook is transferred to the ProjectPythia organisation, use https://mybinder.org wherever the steps below say https://binder.projectpythia.org; the Pythia Binder launches only that organisation’s repositories.

The simplest way to interact with a Jupyter Notebook is through Binder, which enables “one click” execution in the cloud. Simply navigate your mouse to the top right corner of the book chapter you are viewing and click on the rocket ship icon (see screenshots here), and a text box will appear. Type or paste the Pythia Binder link (https://binder.projectpythia.org) and click “Launch”. After a few moments you should be presented with a notebook that you can interact with. You’ll be able to execute code and even change the example programs. At first the code cells have no output, until you execute them by pressing Shift+Enter. Complete details on how to interact with a live Jupyter notebook are described in the Pythia Foundations chapter Getting Started with Jupyter.

Note, not all Cookbook chapters are executable. If you do not see the rocket ship icon, such as on this page, you are not viewing an executable book chapter.

Running on Your Own Machine¶

If you are interested in running this material locally on your computer, you will need to follow this workflow:

  1. Clone the https://github.com/glenbuchanan/cesm2-lens-ml-readiness-cookbook repository:

     git clone https://github.com/glenbuchanan/cesm2-lens-ml-readiness-cookbook.git

  2. Move into the cesm2-lens-ml-readiness-cookbook directory

    cd cesm2-lens-ml-readiness-cookbook

  3. Create and activate your conda environment from the environment.yml file

    conda env create -f environment.yml
conda activate cesm2-lens-ml-readiness-cookbook-dev

  4. Move into the notebooks directory and start up Jupyterlab

    cd notebooks/
jupyter lab

Running on the NSF NCAR JupyterHub¶

On the NSF NCAR JupyterHub (Casper/Derecho) create the same environment from environment.yml and pick the kernel it registers; the chapters read the AWS copy of the ensemble, so no GLADE path is needed.
