Finding the data: CESM2 LENS on AWS

Does the autumn ENSO state predict a wet Front Range winter? This cookbook answers that one classification question on NSF NCAR’s CESM2 Large Ensemble, following NSF Unidata’s Supervised Machine Learning Readiness. This chapter frames the question and finds the data.

Code: Apache-2.0 · Content: CC BY 4.0 · Data: NCAR CESM2 Large Ensemble Cloud-Optimized Dataset (Grover & Banihirwe 2021, Grover & Banihirwe (2021)) and Rodgers et al. 2021 (Rodgers et al. (2021)), UCAR Data Terms of Use; Community Earth System Model v2 Large Ensemble (CESM2 LENS) was accessed on 2026-10-20 from https://registry.opendata.aws/ncar-cesm2-lens.

Drafted with AI assistance (Anthropic’s Claude) from cited sources, under the author’s direction, and reviewed by the author in several full read-throughs.

Text and code were checked against those sources and the notebooks’ own outputs by the author’s automated checks (not in this repository) and by separate AI review sessions (also Claude); no human subject-matter expert has reviewed it yet.

Overview¶

A classifier will read one number, a member’s autumn Niño 3.4 state, and say whether that member’s coming Front Range winter will be wet. This chapter frames that question as a decision, finds the data in the intake-esm catalogue, records it in a Metadata Document, and loads the committed table.

The spine is Unidata’s (Apache-2.0), except that the split is by ensemble member (chapter 3). Terms are in the glossary; shared code is in lensml.py, and show() prints a function’s source.

The question, as a decision¶

The person who acts on the answer is a forecaster drafting a local winter-outlook briefing, such as NWS Boulder’s (2020) or NWS Pueblo’s (2025). Pueblo’s relays the Climate Prediction Center’s official lean and reports what the ENSO state statistically suggests locally. A “wet” call right more often than the base rate, without missing most wet winters, would let it do that beside CPC’s “equal chances”, as Pueblo’s 2025 briefing did: “Statistically, warmer and drier SE CO, but CPC’s forecast is equal chances”.

Every parameter in lensml.py is a design decision with its reason; changing one is a trial you record. The seed is declared once and passed down, never np.random.seed() (scikit-learn’s Common pitfalls, §12.3.3). The figure draws the two boxes from those parameters.

def span(box):
    """A box as degrees with hemispheres, from its slices on the 0-360 grid."""
    y0, y1 = box["lat"].start, box["lat"].stop
    x0, x1 = box["lon"].start, box["lon"].stop

    def lat(y):
        return f"{abs(y):g}°{'S' if y < 0 else 'N'}"

    def lon(x):
        return f"{x:g}°E" if x <= 180 else f"{360 - x:g}°W"

    return f"{lat(y0)}–{lat(y1)}, {lon(x0)}–{lon(x1)}"

Try it: the expected sign

Before any data cell runs, write down the sign you expect: does a warm autumn Pacific make a wetter or a drier Front Range winter? NWS Boulder places El Niño’s wet signal east of the Divide mainly in late winter and spring, and La Niña’s dry signal across “the entire cold season”, so SEASON matters: DJF is committed; FMA costs a rebuild (below).

Framing: Unidata’s three questions¶

Unidata opens every analysis with three questions, so that the target answers someone’s decision.

Try it: frame it yourself first

Before opening the worked answers, write your own: three simple solutions a model must beat, whether the requirements can be met, and the question as one decision.

The worked answers

Does a simpler solution exist? Three, and a model is measured against them, not assumed to beat them.

Simple solutionWhat it predictsWhat it sets
always-dry“dry” every wintera bar on accuracy only (wet precision and recall are 0)
always-wet“wet” every winterrecall 1 at precision = the base rate: the bar every precision is read against
Niño-sign rule“wet” when the autumn Niño 3.4 anomaly is positivethe physical prior (NWS Boulder east of the Divide: El Niño wetter, La Niña drier); no bar

Can machine learning requirements be met? On the data side, yes: the catalogue holds monthly PRECC, PRECL and TS for every historical member in both forcing variants. On the physics side the honest prior is a small effect: Stagge et al. (2023) find the ENSO winter-precipitation signal over the Intermountain West is a north–south dipole, “the northern pole … north of 40° N” and “the southern pole … south of 35° N”, with the Front Range (about 38.5–40.5° N) mostly between them, its northern edge at the northern pole’s 40° N, and the northern pole’s sign reversed (La Niña wetter). The signal is measured here, not assumed.

Which scientific question should be answered? “Given the autumn Niño 3.4 state in a CESM2 LENS member, will that member’s coming Front Range winter be wet — above the one pooled threshold that marks the upper third of the training members’ detrended winters?”

The catalogue on AWS¶

The catalogue forces two design facts: there is no monthly PRECT, so the target is PRECC + PRECL; and there is no variable named SST, so the Niño 3.4 index is built from atmospheric TS over open ocean. The first cell lists the six stores; the second computes what a box subset reads. Offline, each prints OFFLINE and the chapter runs from the cache.

The Metadata Document¶

Unidata’s Metadata Document records the data in four parts (general, structure, quality, provenance), each row naming its evidence. The three Quality rows carry into later chapters: the smbb half has no ocean TEMP, so both halves use TS; smbb also differs in forcing (smoothed biomass burning, 1990–2020), so chapter 2 checks base rates per half; and early members “should not be considered … independent”, so chapter 3 measures what independence is left.

The member-winter table¶

Two box means per member read the volume the chunking line computes, so the derivation runs once and writes data/member_winters.csv for every chapter. Its reader asserts that the header records the current parameters and an access= date equal to ACCESS_DATE (the cache header matches lensml.py line). The committed header predates AUTUMN_MONTHS; the reader assumes SON and prints a line saying so.

show(derive_member_winters, load_cache)

Rebuilding. REBUILD = True re-derives the table from S3: 33 minutes for the full ensemble on a fast link (2026-10-20), an hour or more on home broadband; fewer members is a quick sample. A rebuild stamps its own access date (and AUTUMN_MONTHS) into the header; the chapters then ask you to set ACCESS_DATE to match.

Summary¶

The question is a forecaster’s autumn decision, measured against three simple rules. The data are in a Metadata Document whose rows point at printed evidence; the table is asserted against the parameters on every read (the cache header matches lensml.py line).
