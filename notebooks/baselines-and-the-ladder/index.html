Baselines and the ladder

Three rules that fit nothing, then three models of rising flexibility, read against the base rate: accuracy alone would crown the rule that never calls a wet winter.

Overview¶

  1. Rung 0: three rules that set the bars.

  2. Rungs 1–3: logistic regression, a decision tree and gradient boosting, built from scikit-learn.

  3. Precision, recall and average precision against the base rate.

  4. The decision threshold as a trial.

The glossary defines ladder, rung, incumbent, register, base rate and wet-call share.

The ladder¶

Unidata compares two algorithms; this cookbook climbs a ladder of three above rules.

RungEstimatorWhat you can read from it
0always-dry · always-wet · Niño-sign rulethe bars and the physical prior
1LogisticRegressionone coefficient, in log-odds
2DecisionTreeClassifierthe rules themselves
3GradientBoostingClassifierlittle directly

Always-dry bars accuracy, always-wet bars precision (at the base rate), and the sign rule is the prior every rung must beat.

Why these three rungs

Rung 1 because one log-odds coefficient is the first thing a scientist wants to read. Rung 2 because it can bend where a line cannot — does the signal live only in strong events, as NWS Boulder’s “moderate to strong” suggests? — under a depth cap. Rung 3 as the most flexible model a one-input table can justify; the table is small, so the guide’s own note points at GradientBoostingClassifier rather than the histogram variant. The costs: rung 1 assumes a linear boundary; a tree “can be unstable” and overfits without a depth or leaf limit; boosting, “an excellent model … for tabular data”, costs run time, readability and more settings to record.

Seeds and Pipelines

Every estimator with randomness takes random_state=seed from the declared RNG_SEED, so a fit can be rerun, and scaling sits inside a Pipeline, so a transform never sees the scoring side of a fold.

The cell builds all six; SignRule, the one custom estimator, prints its source. The asserts check the six against lensml.ladder, which chapters 5–7 reuse.

show(SignRule)  # rung 0c: wet if the autumn Niño 3.4 anomaly is positive

seed = RNG_SEED
models = {
    "always-dry": DummyClassifier(strategy="most_frequent"),
    "always-wet": DummyClassifier(strategy="constant", constant=1),
    "nino-sign": Pipeline([("rule", SignRule())]),
    "logistic": Pipeline(
        [
            ("scale", StandardScaler()),
            ("clf", LogisticRegression(random_state=seed)),
        ]
    ),
    "tree": DecisionTreeClassifier(
        max_depth=3, min_samples_leaf=20, random_state=seed
    ),
    "boosting": GradientBoostingClassifier(
        n_estimators=100, max_depth=2, learning_rate=0.05, random_state=seed
    ),
}
module = ladder(seed)  # the same six, as chapters 5-7 build them
assert list(models) == list(module)
assert all(
    repr(m.get_params()) == repr(module[k].get_params())
    for k, m in models.items()
)

Validate: confusion matrix, precision, recall¶

Every number below comes from members the fit never saw. Rows are true, columns predicted; precision (for wet) reads down “pred wet”, recall along “true wet”. called_wet is the wet-call share; accuracy, F1 and average precision (AP) sit beside them.

Two estimators of precision and recall

precision_fold / recall_fold are the mean (± SD) of per-fold values, a fold with no wet call contributing 0. precision_pooled / recall_pooled are one division over the summed matrix, which is what the figure draws. F1 and AP are there because precision or recall alone can be gamed by predicting one class; a constant score has AP equal to the base rate, and a random one about the base rate.

summary = pd.DataFrame(
    {
        name: dict(
            precision_fold=s["precision"].mean(),
            precision_sd=s["precision"].std(ddof=1),
            recall_fold=s["recall"].mean(),
            recall_sd=s["recall"].std(ddof=1),
            **pooled(cm),
            called_wet=cm[:, 1].sum() / cm.sum(),
            accuracy=s["accuracy"].mean(),
            f1=s["f1"].mean(),
            ap=s["ap"].mean(),

        for name, (s, cm) in results.items()

Why accuracy misleads¶

Find the highest accuracy, then read that rung’s called_wet: with a base rate near one third, never calling wet is right two times in three. A weak-signal model rarely clears the default 0.5 threshold, so its near-zero recall is an operating point, not a verdict; ap, which reads the ranking at every threshold, says whether a rung separates wet from dry at all.

Try it: the bars, and the matrix by hand

Which rung-0 rows bar accuracy and precision, and where does the sign rule’s precision sit against the always-wet bar? Then compute the nino-sign matrix’s precision and recall by hand, naming its counts hits, false alarms, misses and correct rejections (POD = recall, FAR = 1 − precision).

The same table in MET

MET, the Developmental Testbed Center’s verification package, prints the same four counts with rows = forecast and columns = observation, “Yes” first: read every cell off the axis labels, not off a remembered corner.

The decision threshold is a trial¶

The decision is a statistical statement in a briefing, and the two errors cost differently. A missed wet winter (recall falls) leaves the briefing at CPC’s “equal chances” — a cheap miss. A false alarm (precision falls) puts “statistically wetter” in a briefing before a dry winter — the costlier error, this cookbook assumes, for an office whose briefing is read as guidance.

Lowering the threshold from 0.5 to the designed base rate (1 - WET_QUANTILE) trades precision for recall along the same ranking, adding no skill: the threshold table below prints the same ap at both. The cell only shows this; a threshold you keep is a chapter 5 trial (FixedThresholdClassifier), and once this table has been read, that trial is no longer blind.

# sklearn's default, and the designed base rate
thresholds = [0.5, 1 - WET_QUANTILE]
rows = []
for thr in thresholds:
    m = FixedThresholdClassifier(
        clone(models["logistic"]),
        threshold=thr,
        response_method="predict_proba",
    )
    s, cm = run_folds(m, train, RNG_SEED, S.n_folds)
    rows.append(
        dict(
            model="logistic",
            threshold=round(thr, 3),
            **pooled(cm),
            f1=s["f1"].mean(),
            ap=s["ap"].mean(),
            predicted_wet=int(cm[:, 1].sum()),
            of=int(cm.sum()),
        )
    )
pd.DataFrame(rows).round(3)

Summary¶

Rung 0 sets two bars and a prior; three scikit-learn models climb above it. Accuracy rewards never calling wet, so every rung is read on precision, recall and AP against the base rate. A threshold moves the operating point, not the ranking: a trial to record, not a default to change.
